Create a Giftable Reward System for my idle game backend. The intended UX flow is:

Complete Quest/Mission (Job completes)
→ System creates a Notification with a Gift attachment
→ Player opens gift modal
→ Player claims gift
→ Server grants rewards (e.g., a new Bird)
→ Gift is marked claimed and can’t be claimed again

============================================================
GOALS & CONSTRAINTS
============================================================

- Server-authoritative (no client-side granting).
- Idempotent and exploit-resistant (safe for retries).
- Fully auditable chain:
  Job → EventInstance (optional) → GiftInstance → GiftClaimTx → granted entities/items/currency.
- Gift creation does NOT grant rewards.
- Rewards are granted ONLY on claim.
- Gift stores a snapshot of presentation + rewardSpec at creation time.
- Support multiple reward types:
  currency, item, entity (bird), cosmetic, loot table, bundle.
- If already claimed, claim endpoint must return original result (idempotent).
- Use server timestamps only.

============================================================
5) SERVICE: createGiftForPlayer
============================================================

Function signature:

createGiftForPlayer(playerId, giftDefId, sourceType, sourceId, idempotencyKey)

Steps:

1) Load GiftDefinition.
2) Enforce limitPerPlayer.
3) Compute expiresAt if defined.
4) Create GiftInstance:
   - status: UNCLAIMED
   - idempotencyKey
   - snapshot: { presentation, rewardSpec }
   - sourceType/sourceId
5) Create Notification:
   - type: "gift"
   - title/body from snapshot
   - attachment: { type: "gift", giftId }
   - sourceType: "Gift"
   - sourceId: giftId
6) Ensure idempotency:
   - If GiftInstance with same idempotencyKey exists, return existing.
   - Do not duplicate notifications.

============================================================
6) ENDPOINTS
============================================================

GET /gifts?status=unclaimed
Returns list of gifts (presentation + id).

GET /gifts/:giftId
Returns gift details.

POST /gifts/:giftId/claim
Server must:

1) Begin DB transaction.
2) Lock gift row.
3) Validate ownership + status UNCLAIMED.
4) If already CLAIMED:
     return existing GiftClaimTx.
5) Create GiftClaimTx:
     seed = sha256(giftId + playerId + createdAt)
6) Resolve rewardSpec:
     - currency → increment wallet
     - item → add inventory
     - entity(bird) → create BirdInstance
     - lootTable → resolve via seed
     - bundle → recursive resolve
7) Record grants in GiftClaimTx.grants.
8) Update GiftInstance:
     status = CLAIMED
     claimTxId = GiftClaimTx.id
     claim.claimedAt = now
9) Commit transaction.
10) Return claimTx + grant summary.
